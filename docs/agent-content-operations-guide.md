# Each Spirit 運用・コンテンツ作成エージェント向け共有情報

更新日: 2026-06-20

このドキュメントは、Each Spirit のレポジトリ全体を把握していないエージェントが、運用・調査・コンテンツ作成・軽微なページ改善に協力するための共有前提です。DB の詳細構造や migration の解説は扱いません。

ChatGPT から Supabase MCP で直接 DB 書き込みを行うエージェントには、先に [chatgpt-supabase-content-agent-prompt.md](./chatgpt-supabase-content-agent-prompt.md) を渡してください。

## サイトの目的

Each Spirit は、グルメ・健康・美容・旅行・レジャーなどの選択肢を、比較・ランキング・地域情報・選び方の記事で整理する日本語メディアです。

読者が「どれを選べばよいか」「自分の条件に合う候補は何か」を判断できるように、単なる紹介ではなく、比較軸・確認日・参照元・向いている人・注意点を明確にします。

重視すること:

- 公式情報・信頼できる情報源に基づくこと
- 確認日を残すこと
- 読者が比較できる評価軸を明示すること
- 地域、目的、利用シーンで探しやすい構成にすること
- PR や広告の場合は通常コンテンツと混同させないこと
- SEO / AI検索向けに、タイトル・説明・FAQ・構造化データの材料を揃えること

## コンテンツ追加の基本方針

既存 major カテゴリ内の通常コンテンツは、原則として投稿UIまたは import script 経由で追加します。

対象:

- 記事
- 店舗・商品・スポット・サービス
- ランキング

新しい大カテゴリを作る場合は、単なるデータ追加ではなくページごとの実装が必要です。新規 major category では、URL、一覧ページ、詳細ページ、カードUI、SEO、sitemap、投稿UIの選択肢などをコード側で追加します。

一方で、既存 major 配下の新しい section は投稿UIから作成できます。新規 section は汎用の section ページ、item 詳細ページ、記事/ランキング一覧・詳細への軽い導線で最低限公開できます。既存 section と同等の専用デザイン、地域/target 導線、比較表、専用カードが必要になった場合だけ、section 固有のページ実装を追加します。

判断の目安:

- 既存 section に記事や店舗を増やす: 投稿UI / import
- 既存 major 内に新しい section を増やす: 投稿UIで section を作成でき、汎用公開ページと軽い導線で最低限表示できる。専用デザインや専用比較導線が必要な場合はコード実装が必要
- 新しい major カテゴリを増やす: ページ単位で設計・実装が必要
- 見た目や回遊導線を変える: コード実装が必要

## コンテンツ作成時の基本ルール

記事・店舗・商品・ランキングを作るときは、次の情報を揃えます。

- slug: 英小文字・数字・ハイフン
- タイトル / 説明
- 対象カテゴリ / section
- 地域または目的
- 読者にとっての選び方
- 比較軸
- 公式URL
- 地図URLまたは所在地
- 参照元URL
- 情報確認日
- FAQ
- 注意点や向いていないケース

ランキングでは、順位だけでなく「なぜその順位か」を説明してください。評価軸は3から6個程度を目安にし、読者が比較できる言葉にします。

店舗・商品・スポットでは、公式情報と変更されやすい情報を分けて扱います。営業時間、価格、定休日、キャンペーン、在庫、メニューは変わるため、断定しすぎず、確認日と参照元を残します。

## 投稿UIとコード実装の切り分け

投稿UIで対応するもの:

- 既存 section の記事追加
- 既存 section の店舗・商品・スポット追加
- 既存 section のランキング追加
- 既存 major 配下の新規 section 作成と、最初の店舗・商品・スポット・サービス投入
- 既存コンテンツの本文・説明・画像URL・FAQ・参照元の修正

コード実装が必要なもの:

- 新しい major カテゴリの追加
- 新しい section を既存 section と同等の専用ページにする場合
- 新しいカードUIや詳細ページの専用表示形式
- 新しい検索 facet や絞り込み体験
- 新規 major の sitemap / SEO / JSON-LD 対応
- 投稿UIに新しい入力項目を追加する場合

既存 major 配下の新規 section は、汎用 section ページと汎用 item 詳細ページで公開されます。major トップと汎用 section ページには、section 一覧、掲載一覧、ランキング、記事への基本導線があります。外部エージェントは、まず汎用ページで成立する粒度のコンテンツを作り、専用UIが必要なほど情報設計が固まってからコード実装を依頼してください。

## SEO / AI検索向けの考え方

各ページは、検索結果やSNS共有で内容が伝わるように、タイトル・説明・canonical・OGP・Twitter Card を意識します。

コンテンツ作成時は、以下を意識してください。

- タイトルは具体的にする
- 説明文は対象読者とページ内容が分かるようにする
- FAQ は読者が検索しそうな疑問にする
- 参照元と確認日を残す
- 比較表やランキング理由を曖昧にしない
- 地域名・カテゴリ名・目的語を自然に含める

## エージェントが作業するときの注意

- 古いローカル seed データを正とせず、現在の公開コンテンツは投稿UI / import / Supabase 側を正と考える
- 既存ページの実装を壊さないため、カテゴリ追加時は既存 route / card / SEO のパターンに合わせる
- DB構造の詳細が必要な場合は、このドキュメントではなく migration や Supabase README を確認する
- コンテンツ調査では、公式情報・自治体・観光協会・店舗公式SNS・信頼できる地域メディアを優先する
- 不確かな情報は「要確認」とし、断定しない
- 大きな変更前は、既存カテゴリとURL設計を確認してから進める

## まとめ

Each Spirit は「選ぶ前に、見比べる」ための比較・ランキング型メディアです。

既存 major / section のコンテンツ増強は投稿UI中心で進めます。既存 major 配下の新規 section も投稿UIで開始できます。新しい major カテゴリや、専用デザイン・専用導線を伴う新しい表示体験はページ単位で実装します。コンテンツ作成では、読者が判断できる比較軸、参照元、確認日、FAQ を必ず意識してください。
