# グルメカテゴリ 調査指示テンプレート（飲食店・グルメ系）

## このドキュメントの目的

このテンプレートは、**調査エージェントへの依頼書** です。

調査エージェントが収集・整理したデータをもとに、**別のページ実装エージェント（Codex）が総合的な情報サイトへの反映作業を行います**。そのため、調査エージェントはコードを書く必要はありません。情報を正確に・もれなく・決まった JSON 形式でまとめることに集中してください。

---

## 依頼概要

- **調査カテゴリ**: `ラーメン`
- **調査対象県**: `宮城県`
- **返却形式**: `docs/research-output-schema.md` の JSON 形式

---

## 調査の目的と使われ方

収集したデータは以下の用途で使われます。ページ実装エージェントがこのデータを読み取って、Next.js のウェブサイトに反映します。

| 使われ方 | 対応するデータ |
|---------|-------------|
| 店舗詳細ページ | 各店舗の基本情報・特徴・FAQ・出典 |
| ランキングページ | ランキング構成・評価スコア・選定理由 |
| リージョン一覧ページ | 県の紹介文・SEOテキスト・おすすめ店 |
| 検索・サイトマップ | タグ・slug・カテゴリ分類 |

---

## 調査スコープ

| 項目 | 基準 |
|------|------|
| 店舗数 | **15店舗~**（県を代表する主要エリアを網羅） |
| スタイルの多様性 | 最低4種以上の異なる業態・スタイルを含む |
| エリアの多様性 | 県庁所在地、観光地・地方など関係なく分散 |
| 老舗〜新店バランス | 老舗（創業10年以上）を少なくとも2店含む |
| ランキング数 | **3本以上**（総合1本 + テーマ別3本以上） |

---

## 調査先（優先度順）

1. **公式サイト** — 営業時間・住所・メニュー・価格の一次情報として最優先
2. **食べログ** — 口コミ評点・営業情報の裏付け
3. **観光公式サイト** — 県・市の観光サイト
4. **地元メディア** — 地元タウン誌・地方新聞
5. **Instagram** — 不定休の店舗の最新営業情報・雰囲気確認
6. **じゃらん / るるぶ** — 観光ガイド掲載確認

---

## アウトプット形式

`docs/research-output-schema.md` の仕様に従い、**JSON のみ**で出力してください。Markdown の表や自由記述の調査メモは返却に混ぜないでください。

記事本文を別 `.md` ファイルで作成する場合は、JSON と Markdown ファイルを zip にまとめて返却しても構いません。

### グルメカテゴリで使う content_type

| 調査カテゴリ | `items[].content_type` | `rankings[].content_type` | `rankings[].items[].item_content_type` |
| --- | --- | --- | --- |
| ラーメン | `ramen_item` | `ramen` | `ramen_item` |
| カフェ | `cafe` | `cafe` | `cafe` |

居酒屋、パン屋など未実装カテゴリを調査する場合は、既存実装に合わせた `content_type` を決める必要があります。返却 JSON の `research.notes` に「未実装カテゴリのため content_type 要確認」と明記してください。

### 必須の返却ブロック

- `research`
- `region_overview`
- `items`
- `rankings`
- `articles`（最低1件以上）

---

### セクション1：リージョン概要

以下は `region_overview` に入れてください。

- 県名、短縮名
- この県の `[CATEGORY]` 文化の特徴（2〜3文）
- キャッチコピー
- 代表エリア（5〜7個）
- おすすめ店舗 slug（3件程度）
- SEOタイトル案
- SEO説明文案（120字前後）
- SEOキーワード案（6〜10個）
- ヒーロー画像の検索キーワード案

---

### セクション2：店舗リスト

各店舗は `items[]` に入れてください。DB の `es.items` に対応するため、共通項目とカテゴリ別 `metadata` を分けます。

- 店舗名、slug、content_type、region
- 紹介文は `description`
- カードの推薦文は `editor_comment`
- エリア、住所、電話、価格帯、公式URL、地図URL
- タグ（5〜8個）
- 営業時間、定休日、駐車場、看板メニュー、WiFi/電源/予約などは `metadata`
- FAQ は `metadata.faqs`
- 出典は `metadata.sources`
- 画像候補は安全に使える場合だけ `image_url`、不明なら `metadata.image_research`

---

### セクション3：ランキング構成

ランキングは `rankings[]` に入れてください。各順位は `rankings[].items[]` とし、`item_slug` は必ず `items[].slug` と一致させてください。

#### ランキング1：総合（全店舗）

- `slug`: `[region]-[category]-best`
- `title`: `[県名]の[カテゴリ] おすすめランキング`
- `description`: 評価軸・調査方法が分かる2〜3文
- `conclusion`: 「〜なら○○、〜重視なら△△」形式の編集部結論
- `quick_table_label`: 早見表ラベル
- `criteria`: 5項目程度
- `metadata.sources`: ランキング根拠の出典
- `metadata.faqs`: 2件以上
- `items`: 全店舗、score は 80〜98 を目安

#### ランキング2〜4：テーマ別

テーマ例:

- ラーメン: 醤油、味噌、背脂、駅近、駐車場あり、観光客向け
- カフェ: コーヒー品質、古民家、スイーツ、作業向き、子連れ向き

各テーマランキングは 3〜5店を目安にし、総合ランキングと同じ JSON 構造で返してください。

---

### セクション4：記事

`articles[]` に最低1本以上の記事を入れてください。短い概要記事やランキングの要約ではなく、読者がその地域で店を選ぶ判断材料になる詳細記事を作成してください。

- `body_md` は Markdown 形式
- 本文は 4,000〜6,000字目安
- 見出しは `##` / `###` を使って整理
- 冒頭でその地域のカフェ文化・検索意図・選定方針を説明する
- 地域ごとの違い、初訪問向けの選び方、味や用途ごとの選び方を含める
- 各店舗の紹介は「なぜ選ぶべきか」「どの導線で使いやすいか」「注意点」を含める
- 公式情報や観光情報で確認した事実と、編集部の評価を混同しない
- 本文内に編集者向けメモ、画像権利メモ、実装メモを混ぜない
- ランキングや店舗詳細へ内部リンクしやすいように、`metadata.related_slugs` に関連する ranking slug と item slug を入れる
- 本文を別 `.md` ファイルにする場合は、JSON の `body_md` にファイル名を入れる。取り込み時は本文をDBの `body_md` に保存する
- JSON と Markdown ファイルをまとめた zip で返却しても構いません

---

## 調査時の注意事項

- **実在確認**: 調査時点で実際に営業していることを確認してください
- **不定休の店舗**: 営業時間・定休日に「要確認（公式Instagram参照）」と明記してください
- **公式サイトがない店舗**: SNS・食べログのURLを代わりに記載してください
- **PR・広告掲載なし**: 全店舗はPRなし・自然な評価で選定してください
- **日本語で記述**: 店舗名・説明文・FAQ はすべて日本語で記述してください
- **slug は英語 kebab-case**: `chamonix-niigata` のように英数字・ハイフンのみ使用
