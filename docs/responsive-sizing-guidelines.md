# レスポンシブ時のサイズ設計指示書

このドキュメントは、Each Spirit の各ページを実装・修正する際のサイズ、余白、コンテナ、カード配置の基準です。デザイン装飾の指示ではなく、読みやすさと画面幅の使い方を統一するための実装ルールです。サイズは **Tailwind のユーティリティ表記** で示します。

## Tailwind 換算メモ

Tailwind の spacing は `1 = 0.25rem = 4px`。よく使う対応:

| px | Tailwind | px | Tailwind |
|----|----------|----|----------|
| 12px | `3` | 28px | `7` |
| 16px | `4` | 32px | `8` |
| 20px | `5` | 36px | `9` |
| 24px | `6` | 44px | `11` |
| 48px | `12` | 96px | `24` |

標準スケールに無い値（72px 等）は arbitrary value（例 `p-[72px]`）で指定します。

## 基本方針

モバイルでは、中央寄せの狭いカードを重ねない。画面幅を有効に使い、外枠、内枠、カードの多重構造を減らす。PCでは情報量を増やし、横幅を広く使って比較・一覧しやすくする。

## ブレイクポイント

Tailwind のプレフィックスをそのまま使う（`base` = プレフィックス無し、モバイル限定は `max-sm:`）。

- `base`（〜639px）: スマートフォン前提。プレフィックス無しで指定。
- `sm:`（640px〜）: 大きめスマホ、縦タブレット。
- `md:`（768px〜）: タブレット、2カラム開始候補。
- `lg:`（1024px〜）: PCレイアウト開始。
- `xl:`（1280px〜）: サイド導線や広告枠を置ける幅。

## ページ幅

- モバイルのページ左右余白は `px-4`を基本にする。
- 390px 幅では、主要コンテンツ幅を最低 `w-[calc(100%-32px)]` 確保する。
- `section-shell` 相当の共通コンテナは、モバイルで `max-sm:w-[calc(100%-24px)]` まで狭めてもよいが、カード内にさらに大きい padding を重ねない。
- PCは `w-[min(1360px,calc(100%-40px))]` を基準にし、比較ページや一覧ページは広く使う。

## モバイルのカードルール

- モバイルで「ページ枠 + セクション枠 + カード枠」の3重囲いを作らない。
- 主要セクションの外側カードは、モバイルでは枠と影を弱めるか外す（例 `max-sm:border-0 max-sm:shadow-none`）。
- カード内 padding はモバイルで `px-3`~`px-4`、`py-1.5`~`py-2`、PCで `sm:p-5 lg:p-8`（20〜32px）を目安にする。
- カード同士の縦間隔は `gap-1.5 sm:gap-3`。大きすぎる余白でスクロール量を増やさない。
- 画像付きカードは `aspect-video`（16/9）または `aspect-[4/3]` を固定し、画像読み込みで高さが揺れないようにする。

## セクション余白

- モバイルのセクション上下 padding は `py-6 sm:py-9`。
- PCのセクション上下 padding は `lg:py-12 xl:py-[72px]`（48〜72px）。
- 見出し直下の説明文は `mt-3 sm:mt-4`（12〜16px）。
- セクション間で背景色やカード枠を毎回変えすぎない。読み進める負担を増やさない。

## タイポグラフィ

- モバイルの `h1` は `text-[1.75rem] sm:text-4xl`（28〜36px）、行間は `leading-[1.15]`（1.12〜1.2）。
- モバイルの `h2` は `text-2xl sm:text-[1.75rem]`（22〜28px）。
- カード内見出しは `text-lg sm:text-xl`（18〜22px）。
- 本文は `text-sm sm:text-base`（14〜16px）、行間は `leading-5 sm:leading-8`。状況に応じて `text-xs`も全然使用していい。
- ボタン、バッジ、ステータス表示の文字は `text-xs sm:text-sm`（12〜14px）。長文を詰め込まない。
- viewport 幅に比例したフォントサイズは使わない。`clamp()` を使う場合（例 `text-[clamp(1.55rem,2vw,2.25rem)]`）も上限・下限を明確にする。

## レイアウト切り替え

- モバイルでは基本1カラム（`grid-cols-1`）。
- `md:grid-cols-2`、`lg:grid-cols-3` を検討する。
- 3カラムカードは、`grid-cols-1 md:grid-cols-2 lg:grid-cols-3` にする。
- サイドバー、広告枠、補助導線は `hidden xl:block` で表示する。モバイルでは本文の後ろに移動するか非表示にする。

## アイコンとラベルの配置

- アイコンとタイトル・番号などのラベルは、縦積みにせず **横並び** を基本にする（PC・モバイル共通）。

  ```
  NG（縦積み）        OK（横並び）
  (icon)             (icon) titleや番号
  titleや番号
  ```

- 実装は `flex items-center gap-2`（必要に応じて `gap-1.5`〜`gap-3`）で同一行に並べる。アイコンは `shrink-0` で潰れないようにする。
- 縦積みは高さを無駄に増やし視線移動も増えるため避ける。装飾的に大きく見せたい一部のヒーロー等を除き、横並びを既定とする。

## ヘッダーとナビ

- モバイルのヘッダーは高さを抑え（例 `h-14 sm:h-16`）、ロゴ行とカテゴリナビの余白を小さくする。
- 横スクロールナビは許可するが、左右に十分な見切れ余白を入れ、現在位置が分かるようにする。
- ナビのボタンは高さ `h-9 sm:h-10`、左右 padding `px-3 sm:px-4`を目安にする。

## プロフィール・運営者ページ

- モバイルではプロフィールカードを横幅いっぱいに近づけ、カード内の情報を縦に並べる。
- アイコン画像は `h-20 w-20 sm:h-24 sm:w-24`（80〜96px）の固定枠。本文幅を圧迫する場合は、画像と名前を横並び（`flex items-center gap-4`）、詳細ステータスは下に置く。
- 自己紹介は長文段落ではなく、`担当`、`得意`、`調査スタイル`、`一言` のような短いステータス行で表示する。
- 挨拶やコメント枠は1カード1つまで。コメントの中にさらに枠を重ねない。

## フォーム

- モバイルでは全入力を1カラムにする。
- input、select、textarea の高さは最低 `h-11`（44px）。
- フォーム項目間は `space-y-0` ~ `space-y-2`。
- エラー文は入力欄の直下に置き、ページ上部だけにまとめない。
- 送信ボタンはモバイルで横幅いっぱい（`w-full`）、PCで内容幅または `sm:w-auto` / 最大 `sm:w-60`（240px）程度を許可する。

## 実装チェック

実装後は以下を確認する。

- 390px 幅で本文が狭くなりすぎていない。
- 画面内に外枠が何重にも見えていない。
- 横スクロールが本文全体に発生していない。
- ボタンやバッジ内の文字が折れすぎていない。
- カード内カードが連続していない。
- ファーストビューで主要見出しと次の内容の一部が見えている。
- PCでは余白が余りすぎず、一覧・比較・サイド導線に使えている。
