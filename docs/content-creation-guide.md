# コンテンツ作成ガイド（管理画面の使い方）

> このドキュメントは **Each Spirit のコンテンツ作成担当者** 向けの実務マニュアルです。エンジニアでなくても、管理画面（Admin UI）から **記事 / 店舗・商品 / ランキング** を作成・編集・公開できるようにすることを目的にしています。
>
> 関連: データ構造の正は [items-data-model.md](./items-data-model.md)、URL/slug 規則は [content-display-path-slug-spec.md](./content-display-path-slug-spec.md)。本ガイドは「どこをどう触れば、何が公開されるか」を運用目線でまとめたものです。

---

## 0. まず結論（最短ルート）

1. **ログイン**して管理権限を持っていることを確認（→ §1）。
2. ブラウザで **`/account/manage`**（コンテンツ管理）を開く。
3. 右上のボタンから作りたいものを選ぶ：**記事を作成 / 店舗・商品を作成 / ランキングを作成 / 画像をアップロード**。
4. フォームを埋める。**本文や説明は「事実ベース＋出典」**が大原則（→ §3）。
5. **プレビューで確認** → **公開**（または下書き保存）。
6. 公開すると保存時に自動でページ再生成され、すぐにサイトへ反映されます（→ §8）。

---

## 1. 前提：アカウントと管理権限

### 1-1. 管理権限の仕組み
管理画面（`/account/manage` や各編集ページ）は **管理者として登録されたメールアドレス**でログインしている人だけが使えます。判定は `es.admin_users` テーブルで行われます（`email` が登録済みかつ `enabled = true`）。

- 一般ユーザーとしてログインできても、`admin_users` に無ければ管理画面は開けません（`Unauthorized` / ログインへリダイレクト）。
- **新しい担当者を追加する手順**（管理者・エンジニア側の作業）：
  1. その人に通常どおり **サインアップ**してもらう（`/auth` からアカウント作成）。
  2. `es.admin_users` にそのメールアドレスを `enabled = true` で登録する（DB作業）。
  3. 反映後、その人は `/account/manage` を開けるようになります。

> メールアドレスは小文字で照合されます。サインアップ時のメールと登録メールを一致させてください。

### 1-2. ログイン
- ログイン: `/auth`（ログイン / サインアップ）。
- マイページ: `/account`。コンテンツ管理は `/account/manage`。

## 2. 管理画面の地図（どこに何があるか）

| 画面 | URL | 用途 |
|---|---|---|
| コンテンツ管理（ハブ） | `/account/manage` | 既存の記事・店舗/商品・ランキングを一覧＆検索して編集。新規作成への入口 |
| 記事を作成 | `/account/articles/new` | 記事（読み物・ガイド）の新規作成 |
| 記事を編集 | `/account/articles/{id}/edit` | 既存記事の編集（一覧の「編集」から） |
| 店舗・商品を作成 | `/account/items/new` | item（店舗・商品・作品・人物など）の新規作成 |
| 店舗・商品を編集 | `/account/items/{id}/edit` | 既存 item の編集 |
| ランキングを作成 | `/account/rankings/new` | ランキングの新規作成 |
| ランキングを編集 | `/account/rankings/{id}/edit` | 既存ランキングの編集 |
| 画像アップロード | `/account/storage` | 画像をストレージに保存して URL を得る |

`/account/manage` の一覧では各行に「表示（公開ページを見る）」「編集」リンクがあり、ステータス（公開/下書き）も確認できます。

## 3. 全コンテンツ共通の原則

サイトの信頼性（E-E-A-T）を守るための約束ごとです。**ここが品質の8割**です。

1. **事実ベースで書く。** 推測や誇張ではなく、確認できた事実を書く。
2. **出典（sources）を必ず付ける。** 公式サイト・自治体情報・地図・公式SNS・信頼できる地域メディアなど。各出典に **確認日（collectedAt）** を入れる。
3. **既存の出典・確認日を消さない。** 編集時は原則として既存の参照情報を保持し、更新があったら追記・日付更新する。
4. **画像は権利に注意。** 自前アップロードか、出典が明確な公式画像のみ。出典名・URLを必ず明記する。
5. **slug は一度公開したら変えない。** URL が変わってリンク切れ・SEO 評価リセットの原因になる。slug は英小文字・数字・ハイフン（kebab-case）。例: `niigata-ramen-first-guide`。
6. **カテゴリ名・section 名は表記揺れを避け、既存を再利用する。**
7. **公開前に必ずプレビューで確認。**

## 4. 3種類のコンテンツと使い分け

| 種類 | 何を作るか | 公開URLの形 |
|---|---|---|
| **記事 (article)** | 読み物・ガイド・比較解説などの「文章コンテンツ」 | `/articles/{記事カテゴリ}/{slug}` |
| **店舗・商品 (item)** | 個別の対象（ラーメン店・プロテイン・アニメ作品・人物・施設など）の「詳細ページ」 | `/{大カテゴリ}/{section}/{種別}/{slug}`（例 `/health/protein/products/xxx`） |
| **ランキング (ranking)** | 既存 item または手入力項目を順位付けした「比較ランキング」 | `/{大カテゴリ}/{section}/rankings/{slug}` |

プロテインランキングだけは目的別 target を持つため、公開上の正規URLは `/health/protein/{target}/rankings/{slug}` です。`/health/protein/rankings/{slug}` は互換用の入口として正規URLへ寄せます。

### 依存関係（作る順番）
- **ランキングは既存 item 参照と手入力項目の両方に対応します。** 個別詳細ページも作りたい対象は先に item として作成し、速報・候補リスト・外部サービス比較など item 化前の対象は手入力項目として登録できます。
- 記事は単独で作れます（item と紐づけたい場合は大カテゴリ・section を選ぶ）。

### 大カテゴリと section
- 大カテゴリ: `food` / `health` / `beauty` / `travel` / `entertainment` / `leisure`。
- section: その下のテーマ（`ramen` / `cafe` / `protein` / `hair-salon` / `stays` / `services` / `anime` / `drama` / `spots` など）。
- どの section にどんな入力欄があるかは section ごとに定義されています（エディタが自動で出し分けます）。

## 5. 記事を作る（ArticleEditor）

`/account/articles/new` を開きます。左が入力フォーム、右が**ライブプレビュー**です。

### 5-1. 基本情報
| 項目 | 必須 | 説明 |
|---|---|---|
| 配置 | — | 「大カテゴリ配下に作成」か「独立記事として作成」。**どちらでも公開URLは `/articles/{記事カテゴリ}/{slug}`**。大カテゴリ配下にすると、その大カテゴリ/section のページにも記事が紐づいて表示される |
| 大カテゴリ | 配下作成時 | food/health/beauty/travel/leisure/entertainment。**記事URLには使わない**（紐づけ用） |
| 地域 | 任意 | `niigata` など。**URLには使わない**。関連記事・関連店舗の文脈付け用 |
| 小ジャンル (section) | 配下作成時 | `ramen` / `cafe` / `protein` 等。独立記事では保存されない |
| 記事カテゴリslug | ✅ | **公開URLの分類**。`/articles/{これ}/{slug}` になる。同じテーマは既存カテゴリ名を再利用（フォームに既存候補が出ます） |
| slug | ✅ | URL末尾。kebab-case。ドット不可 |
| 著者名 | — | 既定「Each Spirit 編集部」 |
| タイトル | ✅ | 記事タイトル |
| 説明文 | ✅ | 検索結果や冒頭に出る説明 |
| サムネイル画像URL | 任意 | 直接URL入力、または「サムネをアップロード」ボタンで保存 |

### 5-2. 本文（Markdown）
ツールバー付きのエディタで書きます。記法は **§9 のMarkdownリファレンス**を参照。

- ツールバー: 見出し(H2/H3)、太字、箇条書き、引用/注記、リンク、関連カード、外部画像、**画像アップロード**。
- **画像アップロード**を押すと、ストレージに最適化保存され、本文に `:::official-image` ブロックが自動挿入されます（src が入った状態）。alt・caption・出典を編集してください。
- 本文中の `:::official-image` に `source` / `sourceUrl` を書くと、**記事下部の参照ソースに自動的に追加**されます。

### 5-3. 付随情報
| セクション | 説明 |
|---|---|
| 公式情報・参照ソース | 記事の根拠（公式ページ・地図・SNS・自治体など）。名称 / URL / 種別 / 確認日 / メモ。**事実の裏付けとして重要** |
| 関連記事・関連店舗リンク | 記事下部にカード表示する内部導線。店舗は `/food/ramen/shops/{slug}` のようなURL |
| FAQ | 記事下部のFAQ＋構造化データ(FAQPage)に反映。検索意図に近い質問を |
| タグ / 要点まとめ / このページで分かること | 補足メタ。1行1項目（または カンマ区切り） |
| SEOタイトル / SEO説明 / SEOキーワード | 任意の上書き。空欄ならタイトル・説明から自動生成 |

### 5-4. 保存と公開（重要）
画面下のボタンは**新規と編集で異なります**：

- **新規作成時**: 「下書き保存」 / 「記事を公開」。
- **編集時**: 「更新を保存」（＝**現在の公開状態を維持**して保存）/「下書きに戻す」。
  - 公開中の記事は「更新を保存」で**公開のまま更新**されます。下書き化したい時だけ「下書きに戻す」。
  - 入力欄でEnterキーを押しても、編集時は誤って下書き化されないようになっています。

> **下書き (draft)** は公開ページに出ません。完成するまでは下書きで保存しておけます。

## 6. 店舗・商品（item）を作る（ItemEditor）

`/account/items/new` を開きます。item は「店舗・商品・作品・人物・施設…」など**個別対象の詳細ページ**です。

### 6-1. どの種類を作るか
最初に **大カテゴリ → section** を選びます。選んだ section に応じて、専用の入力欄（例: ラーメンならスープ系統、ホテルなら温泉/食事、商品なら栄養成分など）が自動で出ます。

item の見た目は **item_class（種別）** で決まります：
- `physical_service`（来店型：店舗・施設）/ `intangible_service`（非来店サービス）/ `media`（作品）/ `product`（商品）/ `person`（人物）/ `other`。
- 所在地（住所・地図）欄は来店型のときだけ表示されます。

### 6-2. 基本情報
| 項目 | 必須 | 説明 |
|---|---|---|
| slug | ✅ | URL末尾。kebab-case |
| 名称 | ✅ | 対象の名前 |
| 説明 | — | **短いリード文**（一覧カードやメタ説明に使う。1〜3行程度） |
| 詳細記事（本文・任意） | — | **詳しい解説をMarkdownで**書く欄（§6-4） |
| 地域 (region) | section依存 | 地域分割する section のみ |
| ステータス | — | 公開 / 下書き（既定: 公開） |

### 6-3.「説明」と「詳細記事(body_md)」の違い（重要）
- **説明 (description)** = 短いリード文。一覧カード・検索結果・ページ冒頭に出る要約。
- **詳細記事 (body_md)** = ページ本文として表示される**事実ベースの長文解説**。`description` だけだと内容が薄いページを、記事的に厚くするための欄です。
- 表示位置: item ページの **スペック（基本情報・栄養・沿革など）の後ろ、編集部コメントの前**。
- **空欄でもOK。** 入力しなければ何も表示されません（従来どおりのページ）。

### 6-4. 詳細記事エディタ
記事と同等のMarkdownエディタ（ツールバー＋プレビュー＋画像アップロード）です。記法は §9 を参照。事実ベースで、出典は「拡張情報 > 出典 sources」に入れてください。

### 6-5. section の詳細欄
選んだ section 固有の項目（営業時間・定休日・駐車場・温泉・フレーバー・原作タイプ…など）。表示される欄を埋めてください。

### 6-6. 共通情報
- 画像URL / 公式URL（全型）。
- （来店型のみ）エリア・住所・電話・価格帯・地図URL。
- タグ（カンマ/改行区切り）。
- 編集部コメント（編集部視点の短い所感。本文 body_md とは別）。

### 6-7. 拡張情報（任意）
複数行の項目は **「1行1件・各値を半角 `|` で区切る」** 形式です。空欄は保存されません。

| 欄 | 区切りの順番（`|`） | 例 |
|---|---|---|
| 出典 sources | `URL \| タイトル \| 種別 \| 確認日 \| 備考` | `https://… \| ○○公式 \| official \| 2026-06-20 \| 営業時間確認` |
| FAQ | `質問 \| 回答` | `駐車場は？ \| 7台あります` |
| 沿革・経歴 history | `日付 \| 内容` | `2020-04-01 \| 開店` |
| 視聴/購入/利用 service_model | `サービス名 \| URL \| 備考` | `Netflix \| https://… \| 見放題` |
| 関連リンク related_link | `ラベル \| URL` | `公式メニューを見る \| https://…` |

その他：ジャンル（genres）、画像alt、画像出典 名称/URL、SEO上書き（タイトル/説明/追加キーワード）。

### 6-8. 食品商品の栄養成分
section が食品商品（プロテイン等）の場合、栄養成分の数値欄（1食量・カロリー・タンパク質・脂質・炭水化物・糖質・食物繊維・食塩相当量・基準=1食/100g）が出ます。保存すると専用の栄養データとして格納され、ページに**栄養成分テーブル＋PFCバー**で表示されます。

### 6-9. 保存
画面下の「作成する / 更新する」で保存。ステータスは上の「ステータス」セレクトで決まります（既定は公開）。

## 7. ランキングを作る（RankingEditor）

`/account/rankings/new` を開きます。ランキング項目は **既存 item を選ぶ** か、**手入力で項目を作る** かを行ごとに選べます。

### 7-1. 基本情報
| 項目 | 必須 | 説明 |
|---|---|---|
| カテゴリ(section) | ✅ | どの大カテゴリ/section のランキングか |
| slug | ✅ | URL末尾。kebab-case |
| タイトル | ✅ | ランキングの題名 |
| ステータス | — | 公開 / 下書き（既定: 公開） |
| 地域 | section依存 | 地域別ランキングの場合 |
| 目的(target) | 一部section | protein など「目的別」を持つ section のみ |
| 説明 / 結論 / 一覧見出し | 任意 | リード文・まとめ・表のラベル |
| 評価軸 (criteria) | 任意 | 比較の観点。1行1項目 |
| タグ | 任意 | |
| 最終更新日 | 任意 | |

### 7-2. ランキング項目
- **既存item**: 同じ section の item を選び、順位・スコア・理由・PR表示を設定します。保存時に item と紐づき、公開ページでは item 詳細へ内部リンクします。
- **手入力**: 表示名、項目slug、説明、外部URL、画像URL、価格帯、エリア、タグ、順位・スコア・理由・PR表示を入力します。item が未作成でもランキングに掲載できます。
- item として詳細ページを育てたい対象は、後から item を作成してランキング行を「既存item」に切り替える運用ができます。

### 7-3. 保存
「作成する / 更新する」で保存。ランキング項目もまとめて保存されます。

## 8. 公開と反映タイミング

- **保存＝即反映**：記事・item・ランキングを保存すると、対象ページとその一覧・サイトマップが自動で再生成されます（on-demand revalidate）。通常は保存後すぐにサイトに反映されます。
- **下書き (draft)** は公開ページ・一覧・検索に出ません。
- サイトは基本 ISR（30日ごとの再生成）ですが、上記のとおり保存時に即時反映されるので、担当者が手動で何かする必要はありません。
- 反映が見えないときはブラウザのスーパーリロード（キャッシュ無視）を試してください。

## 9. 本文 Markdown 記法リファレンス

記事の本文・item の詳細記事は、共通の記法で書けます（独自の `:::` ブロックを含みます）。

### 基本
```md
# 大見出し（H1）
## 見出し（H2）
### 小見出し（H3）

段落はそのまま書きます。空行で段落が分かれます。

**太字** と `コード` が使えます。
[表示テキスト](/internal/path) … "/" で始まると内部リンク
[表示テキスト](https://example.com) … 外部URLは別タブで開く

- 箇条書き
- 箇条書き

1. 番号付き
2. 番号付き

> 引用ブロック
```

### 表
```md
| 項目 | 値 |
| --- | --- |
| A | 1 |
| B | 2 |
```
（2行目の `---` 区切りが必須）

### 画像（シンプル）
```md
![代替テキスト](https://example.com/image.jpg "任意のキャプション")
```

### 注記ボックス `:::note`
```md
:::note
補足や注意書きをここに入れます。
:::
```

### 公式画像（出典つき）`:::official-image`
```md
:::official-image
src: https://example.com/photo.webp
alt: 画像の説明（代替テキスト）
caption: 画像の下に出る説明文
source: 出典名（例: ○○公式サイト）
sourceUrl: https://example.com/
:::
```
- **画像アップロードボタンを使うと、このブロックが自動で挿入**されます（src 入り）。alt・caption・出典を整えてください。
- `source` と `sourceUrl` を入れると、記事では参照ソース一覧にも反映されます。

### 関連カード `:::link-cards`
```md
:::link-cards
- [関連記事タイトル](/articles/ramen/example) - カードに出る短い説明
- [別の関連ページ](/health/protein/beginner/rankings/example) - 説明
:::
```

### アフィリエイトカード `:::affiliate-card`
```md
:::affiliate-card
query: ザバス ホエイプロテイン100
title: ザバスを通販で探す
description: 商品名・価格・在庫はリンク先で確認してください。
:::
```
- `query` は楽天・Amazonなどの検索語です。商品名・用途・ブランド名など、ページ文脈に近い語にしてください。
- 表示にはアフィリエイト platform 設定が必要です。未設定の場合はプレビュー用の簡易表示になります。

### 補足
- 先頭の frontmatter（`--- … ---`）や HTML コメントは表示されません。
- **改行コードは自動で正規化**されるので、コピペ元が Windows 改行（CRLF）でも崩れません。気にせず貼り付けてOK。

## 10. 画像の扱い

### 推奨：アップロード
- 記事/詳細記事エディタの「画像アップロード」、または `/account/storage` から保存。
- アップロード時に **WebP へ最適化**して保存し、URL を自動挿入します（iPhone の HEIC も自動変換）。
- これが一番安全（表示・権利・最適化が揃う）。

### 外部URLを使う場合の注意
- サイトは**許可されたホストの画像URLしか表示できません**（next/image の制約）。許可外URLはプレースホルダーになります。
- 新しい配信元（公式サイトのCDN等）を使いたい場合は、**許可ホストの追加**が必要（エンジニアに依頼）。
- いずれの場合も **出典（source / credit）を必ず明記**してください。

## 11. チェックリスト（公開前）

- [ ] slug は kebab-case で、公開後に変えなくて済む確定版か。
- [ ] タイトル・説明（リード文）は内容を正しく表しているか。
- [ ] 本文は**事実ベース**で、推測・誇張になっていないか。
- [ ] **出典（sources）と確認日**を入れたか。公式/信頼ソースか。
- [ ] 画像はアップロード（または許可ホスト＋出典明記）か。alt は適切か。
- [ ] 関連リンク・FAQ・SEO欄など、埋められる補足を入れたか。
- [ ] ランキングの場合、載せた item はすべて存在＆同じ section か。

## 12. よくある質問

**Q. 公開したのにサイトに出ない。**
A. ステータスが「下書き」になっていないか確認。公開で保存していればすぐ反映されます。ブラウザのキャッシュを無視して再読込も試してください。

**Q. 記事を更新したら下書きになってしまう？**
A. 編集時は「更新を保存」を押せば**公開状態のまま**更新されます。下書きにしたい時だけ「下書きに戻す」。

**Q. 本文の `:::note` などが崩れて生テキストで出る。**
A. ブロックは `:::` で始まり `:::` で閉じる必要があります（前後に空行）。改行コードは自動正規化されるので、閉じ忘れ・記法ミスがないか確認してください。

**Q. 画像URLを貼ったのに表示されない。**
A. 許可されていない配信元の可能性。アップロード保存に切り替えるか、許可ホスト追加をエンジニアに依頼してください。

**Q. ランキングに載せたい店が候補に出ない。**
A. その店舗・商品をまず item として、同じ大カテゴリ/section に作成してください。

**Q. 「説明」と「詳細記事」はどう違う？**
A. 「説明」は一覧やメタに出る短いリード文。「詳細記事 (body_md)」はページ本文として出る長文解説です。両方あると、薄いページを記事的に厚くできます。
